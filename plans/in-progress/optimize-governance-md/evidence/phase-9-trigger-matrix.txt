Phase 9b-2 — proving `governance-word-budget` / `governance-readme-completeness`
path-gating fires and skips correctly, on both `pre-push` and `ci`
====================================================================

Context
-------
A trigger list that never fires is worse than no gate — it reads as green. This
proves both directions on both surfaces for the two gates Phase 9 armed, per
the falsifiability rule that an acceptance clause must be checkable in both
directions.

Method
------
Isolated throwaway git fixture (not the real ose-public repo), same pattern as
`phase-1-ci-path-gated.txt`: a minimal `repo-config.yml` carrying the two
gates' real `surfaces:`/`trigger:` declarations verbatim (copied from the real
`repo-config.yml`), exercised via the real CLI binary
(`apps/rhino-cli/target/gate/rhino-cli`) end-to-end. No `origin/main` ref is
created in the fixture, so `gate::run`'s `merge_base_paths()` falls back to
`staged_paths()` (`git diff --cached --name-only`) — the same fallback the
Phase 1 fixture relied on. `git reset && git clean -fd` between cases resets
to a clean baseline; only the file(s) named per case are staged.

Fixture gate declarations (verbatim from `repo-config.yml`):

  governance-word-budget:
    pre-push/ci trigger: repo-governance/, .claude/, .cursor/, .codex/,
      .opencode/, .pi/, .amazonq/, AGENTS.md, CLAUDE.md, repo-config.yml

  governance-readme-completeness:
    pre-push/ci trigger: repo-governance/, .claude/, .codex/, .pi/,
      repo-config.yml

Case 1 — `repo-governance/README.md` staged (expect BOTH execute)
-------------------------------------------------------------------
  $ git status --short
