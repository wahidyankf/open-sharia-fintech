====================================================================

Part 1 — governance-word-budget catches a whole-tree oversized file
---------------------------------------------------------------------
Method: isolated throwaway git fixture (not the real ose-public repo, no
origin configured), exercised via the real CLI binary
(apps/rhino-cli/target/release/rhino-cli) end-to-end.

Re-recorded 2026-08-15 under the six mandatory isolation layers required by
[Git Fixture Isolation](../../../../repo-governance/development/quality/git-fixture-isolation.md)
— the original transcript ran `git add`/`git init`-adjacent writes against
the fixture with no `GIT_DIR`/`GIT_CEILING_DIRECTORIES`/`GIT_CONFIG_GLOBAL`/
`GIT_CONFIG_SYSTEM` and no pre-write escape guard, which a PR review correctly
flagged: the layers were absent, even though the post-run tree was clean and
no escape occurred.

Env-var isolation preamble (all `git`/`rhino-cli` invocations below):
  GIT_DIR=<fixture>/.git
  GIT_CEILING_DIRECTORIES=<fixture>
  GIT_CONFIG_GLOBAL=/dev/null
  GIT_CONFIG_SYSTEM=/dev/null
(`GIT_WORK_TREE` deliberately unset — Standard 2's plain-write-sequence
exception.) Escape guard (Standard 4) asserted `git rev-parse --show-toplevel`
resolves to the fixture root, canonicalized, before `init`, both `config`
writes, and `add` — no trip. Built, exercised, and destroyed from this
session's scratchpad directory, never diagnosed in the primary checkout
(Standard 6).

Fixture `repo-config.yml` (minimal governance-word-budget: + the exact
FR-1.10 `governance-word-budget` gate block):

  governance-word-budget:
    surfaces:
      - glob: "repo-governance/**/*.md"
        target: 400
        warn: 500
        fail: 500
      - glob: "**/README.md"
        target: 700
        warn: 900
        fail: 900

      root: "CLAUDE.md"

  gates:
    - id: governance-word-budget
      type: check
      command: governance word-budget validate
      kind: rhino-cli
      ci-group: governance
      surfaces:
        pre-push: &word-budget-triggers
          scope: path-gated
          trigger: [repo-governance/, .claude/, .cursor/, .codex/,
                     .opencode/, .pi/, .amazonq/, AGENTS.md, CLAUDE.md,
                     repo-config.yml]
        ci: *word-budget-triggers

Fixture content:
  - repo-governance/development/agents/ai-agents.md — 664 words (over the
    500-word fail ceiling), matching the Gherkin scenario's exact path
  - repo-governance/conventions/formatting/linking.md — staged/added
    (the ONLY file git-staged; ai-agents.md itself was never staged)

  $ git add repo-governance/conventions/formatting/linking.md repo-config.yml
  $ git status --short
  A  repo-config.yml
  A  repo-governance/conventions/formatting/linking.md
  ?? repo-governance/development/          (ai-agents.md unstaged)

  $ rhino-cli gate run --surface=pre-push
  Running gate governance-word-budget
  WORD BUDGET: 1 finding(s)
    [FAIL] repo-governance/development/agents/ai-agents.md — repo-governance/development/agents/ai-agents.md is 664 words (over 500-word fail limit); apply progressive disclosure — see repo-governance/principles/content/progressive-disclosure.md
  Error: word-budget audit failed: 1 Fail finding(s); apply progressive disclosure — see repo-governance/principles/content/progressive-disclosure.md
  Error: gate governance-word-budget failed

Result: CONFIRMED — exit 1, the finding names the fixture
(repo-governance/development/agents/ai-agents.md), even though only an
unrelated file (linking.md) was staged. This proves FR-1.12: a matched
trigger validates the whole covered tree, not just the changed files.
