Reading. 'Java quality gate  completed  skipped' is the assertion this checkbox exists to
make. It is taken from the API's own conclusion field rather than from the checks list,
because 'skipping' in the checks list and 'skipped' as a job conclusion are different
strings and only the latter is the job's terminal state.

Why skipped is the correct outcome. The detect job defaults has-java=false and sets it true
only when an affected nx project carries the lang:java tag. No project does yet — DU3 adds
the first one. A job that RAN here would mean the detection is wrong, so this is a negative
assertion with a real failure mode, not a formality. Detect itself concluded 'success',
which rules out the fail-safe fallback path (that path sets every has-* to true and would
have made this job run).
