=== 5. Existing behavior snapshot: content-url.ts / prev-next.tsx / breadcrumb.tsx / tree-builder.ts ===

--- apps/ayokoding-www/src/features/content/core/content-url.ts ---
Single source of truth for the content URL namespace. `contentUrl(locale, slug)` rules:
  - empty / root / "_index" slug            -> `/{locale}`
  - loose top-level page (LOOSE_PAGE_ALLOWLIST[locale]) -> `/{locale}/{slug}`
    en: ["about-ayokoding", "terms-and-conditions"]
    id: ["tentang-ayokoding", "syarat-dan-ketentuan"]
  - everything else (content-tree slugs)     -> `/{locale}/c/{slug}`  (the "/c/" namespace)
Pure function, no IO. Every URL emitter (content page, sidebar tree, breadcrumb, prev/next,
search results, sitemap, feed) imports it.

--- apps/ayokoding-www/src/features/navigation/shell/prev-next.tsx ---
`PrevNext({ locale, prev, next })` renders a prev/next nav pair. Each Link href is built via
`contentUrl(locale as Locale, prev.slug)` / `contentUrl(locale as Locale, next.slug)` — i.e. it
defers 100% of URL-shaping to content-url.ts (no hardcoded path segments). Renders null when both
prev and next are null.

--- apps/ayokoding-www/src/features/navigation/shell/breadcrumb.tsx ---
`Breadcrumb({ locale, segments, showCurrent=false, contentHrefs=false })`.
`hrefFor(locale, segment, useContentUrl)`:
  - segment.href present            -> use it verbatim
  - empty segment.slug              -> `/{locale}`
  - useContentUrl (contentHrefs=true) -> `contentUrl(locale as Locale, segment.slug)`
  - else                            -> `/{locale}/{segment.slug}`  (legacy non-content shape)
Default excludes the last segment (current page shown in h1); showCurrent=true renders it as a
non-link aria-current="page" crumb instead.

--- apps/ayokoding-www/src/features/content/core/tree-builder.ts ---
Pure tree/prev-next builder over ContentMeta[], keyed by `slug` (POSIX path with "/" separators,
no locale/namespace prefix baked in):
  - buildTrees(allContent) / buildTreeForLocale(items): builds per-locale TreeNode[] from flat
    ContentMeta[] by inferring ancestor sections from slug segments (getParentSlug splits on "/").
  - computePrevNext(allContent): groups non-section items by parent slug, sorts siblings by
    `weight`, and returns a Map<"{locale}:{slug}", {prev, next}> of PageLink pairs.
  - findSubtree(nodes, slug): depth-first slug lookup.
None of these four modules encode the "/c/" prefix or any bucket name themselves — that
responsibility is fully centralized in content-url.ts's contentUrl().

=== 9. Environment hazard discovered during Phase 0 (new — not previously documented in this plan) ===
`ls` is shell-aliased to `eza --icons --hyperlink` in this environment (`alias ls='eza --icons
--hyperlink'`). Piping `eza`'s hyperlinked output through `xargs -n1 basename` (as used to freeze
the 37 re-home slugs) corrupts the result: an initial attempt using the aliased `ls -d ... | xargs
-n1 basename` collapsed 37 entries into 2 garbled lines containing embedded OSC-8 escape sequences
(e.g. "version-control-and-gitversion-control-and-git" followed by a stray "]8;;"). Plain `ls | wc
-l` (no xargs) is NOT affected — line counts remained correct (verified 39 under both the aliased
`ls` and `/bin/ls`) — the corruption is specific to piping eza's hyperlinked output into a
word-splitting consumer like `xargs`. Fix used here and recommended for every future `ls -d ... |
xargs ...` pattern in this plan (e.g. any similar slug-freezing or move-loop enumeration in later
phases): invoke `/bin/ls` explicitly to bypass the alias, exactly as this plan's existing `find`
piping rule (section "bare-versus-piped") already requires for `find`. This is a distinct hazard
from the documented RTK/`find` hazard — both are real, both are environment-specific, neither
implies the other.
