Correction (2026-07-25): tag level is @unit only, not @unit @e2e
--------------------------------------------------------------
The 9 un-@wip'd scenarios were initially tagged `@unit @e2e`, mirroring the existing
resizable-sidebar.feature precedent. That precedent's `@e2e` tag is backed by real Playwright step
bindings at `apps/ayokoding-www-fe-e2e/src/steps/resizable-sidebar.steps.ts`; these 9 scenarios have
none yet. `apps/rhino-cli/src/application/e2e_coverage/parser.rs` filters its gap detector to
`@e2e`-tagged scenarios only (`.filter(|s| s.level_tags.contains(&TestLevel::E2e))`), so tagging a
scenario `@e2e` before its Playwright binding exists trips
`nx run ayokoding-www-fe-e2e:specs:e2e:coverage` ("9 new unbound scenario(s) found") — caught by the
Local Quality Gates' `npx nx affected -t test:quick` run. Corrected by retagging all 9 to `@unit`
only. Phase 3 (delivery.md's own title: "Phase 3: Path landing + paths hub + landing hero + e2e")
is where this plan's E2E work belongs; that phase adds `@e2e` back alongside the Playwright step
bindings that justify it, not before.
