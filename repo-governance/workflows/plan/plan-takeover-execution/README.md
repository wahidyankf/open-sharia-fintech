# Plan Takeover Execution Workflow

- [When to Use, and Relationship to plan-execution.md](./when-to-use-and-relationship.md) — States when (and when not) to run this workflow, and that it is a discovery-and-reconciliation layer in front of plan-execution.md rather than a duplicate of it. Use when deciding whether a discovery layer is needed before plan-execution.md, or when scoping what this workflow specifies versus what it inherits from plan-execution.md.
- [Why This Workflow Exists](./why-this-workflow-exists.md) — States the two documented failure modes — hidden uncommitted evidence and concurrent same-plan work in a different location — that motivate a discovery pass before plan-execution.md. Use when explaining why skipping discovery and starting plan-execution.md cold risks re-implementing, abandoning, or orphaning work.
- [Execution Mode and Concurrency Model](./execution-mode-and-concurrency-model.md) — States that this workflow runs as direct orchestration with no delegated discovery agent, and how the N+1 concurrency model applies across repos and cleanup candidates. Use when determining whether discovery probes should fan out across repos, or how many background agents may run concurrently during takeover.
- [Task List Discipline for This Workflow](./task-list-discipline.md) — Extends plan-execution.md's granular 1:1 Task-list mapping to the discovery, anomaly, and cleanup phases this workflow adds before the delivery checklist loads. Use when materializing Tasks for a takeover-execution run, to confirm the granularity each phase requires.
- [Phase A — Discover Every Trace of This Plan: Plan-Identifier and Repo Set](./phase-a-discovery-plan-identifier-and-repo-set.md) — Covers Phase A steps A0 through A1 — resolving the plan-identifier, checking for a handover document lead, and resolving the candidate repo set. Use when starting discovery for a plan-takeover-execution run, before probing any repo for worktrees, branches, or PRs.
- [Phase A — Discover Every Trace of This Plan: Per-Repo Probes and Persistence](./phase-a-discovery-per-repo-probes-and-persistence.md) — Covers Phase A steps A2 and A3 — the ordered six-item per-repo probe list, and persisting raw findings to the takeover-report as they're gathered. Use when running the ordered per-repo discovery probes, or when deciding what to log to the takeover-report during discovery.
- [Phase B — Reconcile Findings Into One Decision](./phase-b-reconcile-findings.md) — Defines the four buckets (nothing found, already delivered, live in-flight, anomaly) Phase A's findings classify into for each candidate repo. Use when classifying a repo's discovered evidence into a single bucket before takeover or cleanup can proceed.
- [Phase C — Take Over the Live Work: Adopt, Freshness Gate, Ledger Rebuild](./phase-c-adopt-freshness-and-ledger.md) — Covers Phase C steps 1-3 — adopting an existing worktree/branch rather than reprovisioning, applying the freshness gate, and rebuilding the file-touch ledger. Use when adopting a repo's already-in-flight worktree or branch instead of reprovisioning over it, or when reconciling it against origin/main.
- [Phase C — Take Over the Live Work: Recording an Existing PR and Reconciling delivery.md](./phase-c-pr-record-and-reconcile-delivery.md) — Covers Phase C steps 4-5 — recording an existing PR's state and CI status, and reconciling delivery.md to the discovered ground truth before Phase E hands off. Use when a Bucket-3 repo already has an open PR to resume against, or when delivery.md needs to be brought in line with evidence discovered elsewhere in Phase A.
- [Phase D — Clean Up Confirmed-Stale Leftovers](./phase-d-clean-up-confirmed-stale-leftovers.md) — Describes the post-classification cleanup pass — the six-check pre-removal sequence, branch deletion, build-artifact scoping, and the never-remove-on-default-to-delete rule. Use when removing a worktree, branch, or build artifact Phase A found that was not the Bucket-3 target Phase C adopted.
- [Phase E — Hand Off to plan-execution.md](./phase-e-hand-off-to-plan-execution.md) — Describes the final handoff step — invoking plan-execution.md per resolved repo, fanning out multi-repo handoffs, and closing the takeover-report. Use when a repo's takeover target (or fresh start) is resolved and ready to hand off to plan-execution.md.
- [Related Documentation — Plan Takeover Execution](./related-documentation.md) — Links to the write-side handover workflow, the workflows this one hands off to, and the conventions Phases C and D apply without modification. Use when navigating from plan-takeover-execution to a workflow or convention it depends on.
