# Cycle Credit Record

The review and its thread state do not durably prove a clean cycle. After every cycle eligible for
clean credit, the orchestrator posts exactly one top-level `IssueComment` immediately after green
CI and the final live-head check, before another cycle or `done`. It uses this complete record:

```html
<!-- ose-pr-review-cycle-credit:v2
{"cycle":8,"review_head":"<40-char scout SHA>","observed_head":"<same SHA>",
 "boundary":"post-ci","credit":"clean",
 "ci":{"head_sha":"<same SHA>","completed_at":"<RFC3339 timestamp>",
 "checks":[{"database_id":123456,"name":"<applicable check>","conclusion":"success",
 "details_url":"https://github.com/<owner>/<repo>/actions/runs/<immutable id>"}]}}
-->
```

`checks` is the complete, deterministically name-sorted set of applicable checks. IDs, URLs, head,
completion time, and conclusions are copied from typed GitHub API objects, not prose. `clean`
requires `boundary: post-ci`, equality of all three SHAs, every applicable check successfully
completed, zero outstanding code-related MEDIUM+, an unused probe class, and no fixer branch
mutation. The orchestrator reads the posted typed object back before continuing. The comment ends
with the canonical `Generated by AI` footer.

## Ineligible Cycles

A posted cycle whose scout pin stops matching the live head still consumes its ordinal but receives
no clean/done credit. Immediately at either mismatch boundary, including a zero-finding review, post:

```html
<!-- ose-pr-review-cycle-credit:v2
{"cycle":8,"review_head":"<40-char scout SHA>","observed_head":"<40-char live SHA>",
 "boundary":"post-review","credit":"ineligible","ci":null}
-->
```

At `post-ci`, `ci` carries the completed checks for their actual `head_sha`; at `post-review` it is
`null`. A pre-post mismatch creates neither a review nor an event. The event is independent of
dispositions, and an underlying `stale-cycle-only` claim remains eligible for fresh-head review.

## Admission and Hydration

Hydration admits these events through
[Cycle Record Authentication](./cycle-record-authentication.md) before reading their marker.
Exactly one authenticated event may name a `cycle`/`review_head`: even byte-identical duplicates,
conflicting credit/boundary/CI evidence, malformed records, and orphaned records stop reconciliation.
Unauthenticated marker text is ignored, including for conflicts.

Hydration derives the consecutive-clean streak **only** from adjacent authenticated v2 events with
`credit: clean`, joined to authenticated reviews whose probe classes were unused. An `ineligible`,
missing, legacy-v1, non-clean, or non-adjacent event breaks the streak; review/thread state never
supplies positive credit. Legacy v1 `ineligible` events remain admissible negative evidence.

Top-level comments remain forbidden for finding replies. This event is cycle state, not review
thread state, and only the orchestrator posts it.
