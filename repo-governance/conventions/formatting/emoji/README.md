# Emoji Usage Convention

- [Principles, Scope, and Purpose](./principles-scope-and-purpose.md) — The accessibility and consistency principles this convention implements, what it covers and does not cover, and the purpose emojis serve in documentation. Use when you need to understand why this repository allows emoji in documentation or what the emoji convention covers.
- [Tasteful Usage: Where Emojis Help and Hurt](./tasteful-usage-where-emojis-help-and-hurt.md) — The jobs emojis can usefully do (section markers, status indicators, navigation signposts) versus the anti-patterns that add visual noise without benefit. Use when deciding whether adding an emoji to a specific spot in a document will help or hurt scannability.
- [Tasteful Usage: Density Cap and Examples](./tasteful-usage-density-cap-and-examples.md) — The soft density limits on emoji per heading and per paragraph, and side-by-side good-vs-bad examples of emoji usage in documentation. Use when checking whether a document has too many emojis, or when you need a concrete good-vs-bad usage example.
- [Emoji Vocabulary: Document, Status, and Process Markers](./emoji-vocabulary-document-status-and-process-markers.md) — The standard emoji vocabulary for document-type markers, status/signal markers, and action/process markers used at the start of headings. Use when picking an emoji for a heading that marks an overview, status, or process/action section.
- [Emoji Vocabulary: Domain-Specific Markers](./emoji-vocabulary-domain-specific-markers.md) — The emoji vocabulary for general technical domains, enterprise/financial-services domains, and AI agent role categorization. Use when picking an emoji for a heading in a technical, financial-services, or AI-agent-related section.
- [Color Accessibility for Colored Emojis](./color-accessibility-for-colored-emojis.md) — How to use colored square emojis for agent categorization accessibly, so color is always supplementary to text and shape. Use when using colored emojis (like the agent-role squares) for visual categorization and you need to keep them accessible.
- [Emoji Usage Rules 1-6](./emoji-usage-rules-1-through-6.md) — Six binding usage rules: semantic consistency, restraint, heading-level placement, no emoji in technical content, accessibility, and no emoji in frontmatter. Use when checking a specific emoji placement against the repository's binding usage rules.
- [Emoji Usage Rule 7: Scope - Where to Use Emojis](./emoji-usage-rule-7-scope-where-to-use-emojis.md) — The full scope rule for where emojis are allowed versus forbidden, with rationale. Use to check whether a file type (docs, agents, config, README) may contain emoji.
- [Document Type Specific Guidelines](./document-type-specific-guidelines.md) — Recommended emojis and worked examples for tutorials, how-to guides, reference docs, explanation docs, plans, and root files like AGENTS.md. Use when writing a new tutorial, how-to guide, reference doc, explanation doc, plan, or root file and want emoji guidance specific to that document type.
- [Migration Strategy and Validation Checklist](./migration-strategy-and-validation-checklist.md) — The phased rollout plan for adding emoji to existing documentation, and the pre-review validation checklist. Use when rolling out emoji to existing documentation or doing a final review pass before committing.
