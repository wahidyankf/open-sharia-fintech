# Multi-Harness Binding Operation — Directory Structure and Format Differences

**Added**: 2026-01-16

This repository maintains **multi-harness compatibility** across multiple AI coding agent platforms. The primary platform binding directory (`.claude/`) is the source of truth; secondary directories (`.opencode/`, `.amazonq/`) are auto-generated by the sync script.

## Directory Structure

```binding-example
.
├── .claude/                 # Claude Code configuration (PRIMARY - Source of Truth)
│   ├── agents/             # agents in Claude Code format
│   ├── skills/             # skills
│   └── settings.local.json # MCP servers configuration
├── .opencode/              # OpenCode configuration (SECONDARY - Auto-generated)
│   ├── agents/             # agents in OpenCode format (synced from .claude/)
│   └── opencode.json       # OpenCode configuration
│                           # (no skill/ mirror — reads .claude/skills/ natively)
└── .amazonq/               # Amazon Q Developer bridge (SECONDARY - Auto-generated)
    ├── rules/
    │   └── 00-agents-md.md # Pointer directing Amazon Q to read AGENTS.md
    └── cli-agents/
        └── ose-default.json # Minimal Amazon Q agent definition
```

## Source of Truth Hierarchy

**`.claude/` is the canonical source**. All updates happen here first, then sync to secondary bindings.

**Making Changes**:

1. Edit agents in `.claude/agents/` directory (PRIMARY)
2. Edit skills in `.claude/skills/` directory (PRIMARY)
3. Run sync: `npm run generate:bindings`
4. Changes automatically regenerate `.opencode/` and `.amazonq/` (SECONDARY)

**Rationale**: Single source of truth prevents conflicts, ensures consistency, simplifies maintenance.

## Format Differences

The primary and secondary harnesses use markdown agents with YAML frontmatter, but with different conventions:

### Tools Format

```binding-example
Claude Code (.claude/agents/) — PRIMARY:
  tools: [Read, Write, Edit, Glob, Grep, Bash]
  (array format with capitalized tool names)

OpenCode (.opencode/agents/) — SECONDARY:
  permission:
    read: allow
    write: allow
    edit: allow
    glob: allow
    grep: allow
    bash: allow
  (permission object, nested YAML — current OpenCode convention;
  the historical boolean flags format `tools: { read: true, … }` is
  deprecated/legacy and no longer emitted)
```

### Model References

```binding-example
Claude Code:
  model: sonnet  # execution-grade
  model: haiku   # fast
  model:         # planning-grade (omit for budget-adaptive inheritance)

OpenCode:
  model: opencode-go/glm-5.2  # thinking-grade/execution-grade equivalent (intentionally identical)
  model: opencode-go/minimax-m3 # fast equivalent
```

### Agent skills Format

**Identical for both platforms** — agent skills use the same SKILL.md format:

```yaml
---
name: skill-name
description: Brief description
context: inline # optional; defaults to inline
---
# Skill Name
Content...
```

**Required fields**: `name` (must match directory name), `description`
**Optional fields**: `context` (inline or fork)

Agent skills are **not mirrored** — the secondary harness reads `.claude/skills/{name}/SKILL.md` natively (no copy or conversion needed).
