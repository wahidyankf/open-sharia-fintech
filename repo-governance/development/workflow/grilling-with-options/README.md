# Grilling-With-Options Convention

- [Principles and Conventions Implemented](./principles-and-conventions-implemented.md) — The principles and companion conventions the Grilling-With-Options Convention implements and respects. Use when tracing why structured multiple-choice grilling is required back to the principles and conventions it respects.
- [Purpose and Scope](./purpose-and-scope.md) — Why structured grilling replaces open-ended prose questions, and what this convention covers versus what it explicitly leaves to other conventions. Use when deciding whether a given design-decision interaction falls under this convention or one of its companions.
- [Rule 1 and Rule 2 — Explore Before Asking; Structured Options](./rule-1-and-rule-2.md) — The requirement to read repo artifacts before grilling, and the 2-4 mutually-exclusive substantive-option cap. Use before composing a grilling question, to confirm the answer isn't already discoverable and that the option count is within bounds.
- [Rule 3 and Rule 4 — Trade-Off Per Option; Exactly One Recommended Option](./rule-3-and-rule-4.md) — The requirement that every option states a context-specific trade-off, and that exactly one option is marked Recommended. Use when writing an option's trade-off sentence or deciding which single option to mark Recommended.
- [Rule 5 and Rule 6 — One Decision Per Question; the Native-Tool Mechanism](./rule-5-and-rule-6.md) — The rule that each question resolves exactly one decision (batching only tightly-coupled ones), and the opening statement of the native-tool-first mechanism. Use when deciding whether two decisions may be batched into one grilling prompt, or when starting to render a grill through a native interactive tool.
- [User Decisions Required Envelope](./user-decisions-required-envelope.md) — The exact outbound envelope a subagent returns to the root orchestrator instead of rendering a user prompt itself. Use when a subagent must hand an unresolved design decision back to the root orchestrator instead of asking the user directly.
- [Resolved User Decisions Envelope](./resolved-user-decisions-envelope.md) — The exact inbound payload the root passes back to a specialist verbatim once the user has resolved every decision, and the validation the specialist must perform on it. Use when the root is constructing the resolved-decisions payload to pass back to a specialist, or when a specialist must validate that payload before proceeding.
- [Staged Native Rendering](./staged-native-rendering.md) — The procedure for rendering a 3-4-leaf decision envelope through a native tool limited to 2-3 options, via branch groups, plus the markdown fallback for non-interactive roots. Use when a native interactive tool's option limit is smaller than the number of substantive leaves in a decision envelope.
- [Markdown Fallback Format](./markdown-fallback-format.md) — The inline markdown option format a genuinely non-interactive root emits when no native multiple-choice tool is available. Use when rendering a grilling question on a root or harness with no native interactive multiple-choice tool.
- [Rule 7 and Rule 8 — Unlisted Answers; Standing Options](./rule-7-and-rule-8.md) — The rule that a user's write-in answer always counts, and the two standing options every grilling question must carry. Use when a user supplies an unlisted answer, or when checking whether a question surfaces both the blank-state type option and the chat option.
- [When This Convention Applies](./when-this-convention-applies.md) — The six contexts where grilling MUST follow this convention's structured format. Use when deciding whether a given interaction requires this convention's structured grilling format.
- [Examples](./examples.md) — PASS and FAIL examples of grilling questions — a well-formed markdown fallback, native-tool usage, and five common violations. Use when checking whether a specific grilling question is well-formed or violates one of the option-structure rules.
- [Validation](./validation.md) — The checklist of conditions that make a grill question valid or invalid. Use as a final checklist before sending any grilling question to the user.
- [Special Considerations and Tools and Automation](./special-considerations-and-tools-and-automation.md) — How grilling narrows to validation passes inside plan-maker, why grilling is a process artifact rather than a document, and the tools that implement and check this convention. Use when grilling is invoked from inside plan-maker, when verifying compliance without a generated artifact, or when identifying which tool implements or checks this convention.
- [Platform Binding Examples — Primary and Secondary Harnesses](./platform-binding-examples-claude-code-and-opencode.md) — How the grill-me skill invokes the native multiple-choice tool on the primary and secondary harnesses, including the example invocation shape. Use when implementing or verifying a grilling interaction on a primary- or secondary-harness root session.
- [Platform Binding Examples — All Other Harnesses](./platform-binding-examples-codex-and-all-other-harnesses.md) — How the root orchestrator invokes a third harness's user-input tool, and the markdown fallback required for any harness without a native interactive tool. Use when implementing or verifying a grilling interaction on that harness, or on a harness with no native multiple-choice tool at all.
