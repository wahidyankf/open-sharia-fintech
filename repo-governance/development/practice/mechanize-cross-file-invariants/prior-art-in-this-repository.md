# Prior Art In This Repository

This pattern already governs several cross-cutting invariants here, each independently arrived at
before being named as one general practice:

- **Harness bindings** (canonical `.claude/agents/` and `.claude/skills/` →
  `.opencode/agents/`, `.codex/agents/`, the generated region in `.codex/config.toml`, and
  non-vendored mirrors under `.agents/skills/`) — generated by `npm run generate:bindings`, checked
  by `npm run validate:sync`. Vendored paths in those secondary roots remain hand-maintained. See
  [File-Touch Discipline](../file-touch-discipline.md) for the same-commit requirement this implies.
- **`repo-config.yml` schema parity** across the byte-identity-bound repos — `rhino-cli repo-config
validate` enforces an identical key set at parse time, so no repo can silently add or drop a key.
- **Git hooks** (`.husky/pre-commit`, `.husky/commit-msg`, `.husky/pre-push`) — thin shims that read
  `repo-config.yml`'s `gate:` surface at runtime via `rhino-cli gate list`/`gate run`, rather than
  hand-maintained command lists per hook.
- **`package.json`'s `lint-staged` block** — emitted from `repo-config.yml`'s per-formatter `command:`
  field via `rhino-cli gate emit --surface=pre-commit`; hand-editing it directly drifts from what the
  registry would produce the next time `gate emit` runs. See
  [PR Merge Protocol § Resolving Merge Conflicts in Generated Files](../../workflow/pr-merge-protocol.md)
  for what this means when such a file has a merge conflict.
