The first twelve scenarios make the interview flow deliberate. They are constructed prompts: use
them to rehearse explanation and verification, not as a substitute for the depth course.

## ex-01 · clarify-functional-vs-nonfunctional

**Concepts**: co-02.

**Scenario**: Split a vague appointment reminder prompt into functional behavior and non-functional constraints.

**Observable check**: Write two named lists before proposing components; verify no item appears in both lists.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-02 · negotiate-scope

**Concepts**: co-03.

**Scenario**: Narrow “design a social network” to one feed-reading flow that fits the timebox.

**Observable check**: State included, excluded, and deferred behavior; confirm interviewer agreement.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-03 · capacity-estimate

**Concepts**: co-04.

**Scenario**: Estimate QPS, storage, and bandwidth for a fictional image-sharing service.

**Observable check**: Show an assumption and units for every figure; connect one figure to a decision.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-04 · high-level-diagram

**Concepts**: co-05.

**Scenario**: Draw the major responsibilities for a reminder service before a deep dive.

**Observable check**: Label each box with its purpose and each arrow with its request or event flow.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-05 · api-sketch

**Concepts**: co-06.

**Scenario**: Sketch create, read, and cancel operations for an appointment reminder.

**Observable check**: Map every operation to a functional requirement and name its input and output.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-06 · data-model

**Concepts**: co-07.

**Scenario**: Model reminders, appointments, recipients, and delivery attempts.

**Observable check**: Name the primary read and write paths and show how the model supports them.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-07 · storage-choice-justified

**Concepts**: co-07, co-16.

**Scenario**: Choose storage for the reminder access patterns.

**Observable check**: State the access pattern, benefit, cost, and why it fits the stated need.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-08 · deep-dive-one-component

**Concepts**: co-20.

**Scenario**: Deep-dive the scheduled-delivery path only after the interviewer asks.

**Observable check**: Explain one component at useful detail, then return to the full request flow.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-09 · name-the-bottleneck

**Concepts**: co-15.

**Scenario**: Find the first limit in a peak delivery burst.

**Observable check**: Tie the bottleneck to an estimate and name the next measurement.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-10 · state-two-tradeoffs

**Concepts**: co-16.

**Scenario**: Explain two choices in a fictional notification design.

**Observable check**: For each, state a concrete benefit and a concrete cost.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-11 · drive-the-round

**Concepts**: co-21.

**Scenario**: Open a design round with a candidate-led agenda and checkpoints.

**Observable check**: The candidate, not the interviewer, announces the next phase of the spine.

**Interview move**: Say the current spine stage aloud before advancing.

## ex-12 · closing-summary

**Concepts**: co-01, co-15.

**Scenario**: Close a design round in one minute.

**Observable check**: Recap scope, design, chief risk, and a next validation step.

**Interview move**: Say the current spine stage aloud before advancing.
