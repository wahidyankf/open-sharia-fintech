Note: `nvim -u before/init.lua` alone does NOT add a sibling lua/ directory to the runtimepath -- only
Neovim's normal XDG-based startup does (stdpath('config')/lua joins the runtimepath automatically, per
co-01). The commands above set XDG_CONFIG_HOME to a throwaway directory whose nvim/ symlinks into this
kata's before/ or after/ tree, so require('config.scratch') resolves exactly the way a real
~/.config/nvim/init.lua would. On-disk lua/config/scratch.lua is reset back to { value = 1 } in both
directories after each verification run, matching the listing shown on the drilling page.
