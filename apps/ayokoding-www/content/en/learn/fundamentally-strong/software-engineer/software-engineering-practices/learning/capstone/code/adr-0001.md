# ADR-0001: cap a single points redemption at 50% of the cart subtotal

## Status

Accepted

## Context

Loyalty points currently have no per-transaction redemption limit: a customer with a large point
balance can zero out an entire cart with points, producing a \$0.00 charge. Finance flagged this as
a fraud-detection blind spot -- a compromised account's points can be laundered into free goods in
one transaction, with no partial-payment signal to review. The fix needs to be small, testable, and
land without disrupting the ordinary redemption flow for the overwhelming majority of transactions
that stay well under any reasonable cap.

## Decision

Cap a single redemption at `MAX_REDEMPTION_FRACTION = 0.5` (50%) of the cart's pre-discount
subtotal, enforced in `redeem_points()` (`redemption.py`, commit `3dedac0`,
`feat(loyalty): cap points redemption at 50 percent of cart subtotal`). A request above the cap
raises `ValueError` rather than silently clamping -- the caller (the checkout flow) decides how to
surface that to the customer (e.g., "redeem up to $50.00 in points on this order"). The failing
test that drove this decision (`test_redemption.py`, commit `acfd018`,
`test(loyalty): add failing test for capped points redemption`) is the executable specification of
the 50% rule. This change bumps the loyalty module from `v1.0.0` to `v1.1.0` (a backward-compatible
addition -- no existing caller's behavior changes for a redemption already under the new cap), with
a corresponding `[1.1.0]` changelog entry under `### Added`.

**Alternatives considered**:

- **No cap, flag large redemptions for manual review** -- rejected: still allows an automated
  account-takeover script to zero out a cart before any human reviews it.
- **A fixed dollar cap (e.g., \$25) instead of a percentage** -- rejected: unfairly restrictive on
  large carts and overly permissive on small ones; a percentage scales with the transaction itself.
- **100% cap (i.e., no limit) with a separate fraud-detection service** -- rejected as the first
  iteration: a standalone fraud service is a larger, slower-to-ship change; the 50% cap is a cheap,
  immediate mitigation that a follow-up fraud service can later relax or replace.

## Consequences

A customer redeeming points for a large chunk (but not all) of a purchase is unaffected -- the 50%
threshold covers the overwhelming majority of legitimate redemptions observed in production. A
customer who wants to fully zero out a cart with points now needs a second transaction (or a
manual override), which is the intended friction. The 50% figure is a starting point, not
empirically tuned against real fraud data yet -- revisiting it once the fraud-detection team has
loss numbers to compare against is expected future work, tracked separately from this ADR.
